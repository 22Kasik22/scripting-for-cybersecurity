3. A directory can be executable because the x permission allows a user to enter or search the directory.

Exercise 2 - Answers

1. auth.log passes the checks. empty.bin fails -s because it is empty. case/logs fails -f because it is a directory.

2. Checking -f first makes sure the path is a regular file before checking its read permission. With &&, Bash stops checking when a test fails.

3. case is a directory and auth.log is a regular file. /dev/null is a character device, not a regular file or directory.

4. guard_clause.sh now returns 2 for a non-regular file, 3 for an unreadable file and 4 for an empty file.

Exercise 5 - Answers

1. [ -f $FILE ] with an empty variable gives a false positive because Bash tests the non-empty string -f. The quoted version works correctly.

2. The broken check_ip.sh uses grep without -F. It can match an incorrect address because dots are treated as regular expression characters.

3. grep -w alone is not enough. It checks word boundaries but still treats dots as wildcards. grep -wF is needed for this example.

Investigation Challenge - Answers

1. 198.51.100.77 made 8 failed login attempts. It is not in intel/iocs.txt and does not appear in the firewall log. The IOC list alone is not enough because it can miss suspicious addresses.

2. 203.0.113.200 is in the IOC list. The firewall blocked it from port 3389, normally used by RDP (Remote Desktop Protocol). auth.log shows failed SSH login attempts. SSH normally uses port 22.

3. 203.0.113.77 appears in access.log but not auth.log. It made HTTP requests to pages including /admin, /wp-login.php, /robots.txt and /assets/app.js. Some requests used sqlmap, curl and python-requests. This suggests web scanning and probing, but it does not prove a successful attack.
